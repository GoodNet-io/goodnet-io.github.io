Tech breakdown

Four building blocks that make GoodNet tick.

Multi-path transport

Every connection is a bundle of paths. A strategy plugin (RTT-optimal, redundant, manual) picks which carrier to send on, switches mid-flight on degradation, and reorders inbound by cryptographic counter — never by socket.

Plugin ecosystem

The kernel exposes a stable C ABI. Plugins compose into the dispatch chain at load time.

  • link-* — TCP, UDP, WebSocket, TLS, IPC, QUIC, ICE NAT-traversal.
  • security-* — Noise XX/IK, PKCS#11 HSM, null (loopback).
  • handler-* — heartbeat, DNS, distributed store, web-api-proxy.
  • strategy-* — RTT-floating multi-path scheduler.
  • bridges-* — C++, JS, Python, Rust.

Identity & HSM

Peer addresses are Ed25519 pubkeys. The signing key can sit in a YubiKey or any PKCS#11 token — kernel never sees the secret. 

// Phase 5 — HSM-backed identity
gn::sdk::Identity id = gn::sdk::Identity::from_pkcs11(
  "/usr/lib/libykcs11.so",
  /*slot*/ 0,
  /*pin*/ getenv("GN_PIN"));
auto core = gn::sdk::Core::with_identity(id);
auto sess = core.connect_to("ice://peer-pubkey-base32");

gssh — peer-pubkey SSH

A native SSH-2.0 server / client that authenticates by GoodNet peer pubkey. No authorized_keys to sync — the address is the credential. 

# dial a host by its pubkey, no DNS or IP
gssh user@QFK4M7N2-XYZ7-A9KL-VBC3-RT8P
